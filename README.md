# 🏛️ 会展中心逛展路径工具

观众选择**展馆入口、目标展位、餐饮区、会议室**，后端综合
「**通道距离 + 楼层换乘 + 拥挤程度**」三因素计算最优逛展路线；
前端**同时展示场馆拓扑图（高亮路线）与中文文字步骤**；
不可达展位明确提示原因与建议。

## 快速开始

```bash
bash run.sh            # 或 PORT=8080 bash run.sh
# 打开 http://localhost:8000
```

仅依赖 **Python 3 标准库**，无需 pip install。

## 功能清单

| 需求 | 实现 |
| --- | --- |
| 选择入口 / 展位（多选）/ 餐饮区 / 会议室 | 左侧表单 + 直接点击拓扑图选点，展位按到访顺序编号 |
| 通道距离 | 每条走廊/展位支路带真实距离（米），步行按 1.25 m/s 计时 |
| 楼层换乘 | 电梯（25s/层）、自动扶梯（40s/层）、疏散楼梯（55s/层），Dijkstra 自动选最快的垂直交通 |
| 拥挤程度 | 4 级拥挤度（畅通/正常/拥挤/非常拥挤）映射为代价系数；提供「优先避开拥挤」开关，自动绕行南环疏解通道 |
| 拓扑图 + 文字步骤 | 右侧 SVG 三层楼面图实时高亮规划路线（步行=琥珀色、电梯/扶梯/楼梯=紫色虚线、序号徽标）；右侧分段中文指引（方向、距离、耗时、拥挤提示、换乘、到达） |
| 不可达提示 | 区分**节点关闭**（B206 今日撤展）与**通道封闭**（C304 东侧施工），给出原因标签、详细说明、处理建议；后续目标自动跳过不可达点继续规划 |
| 总行程概览 | 总步行米数、预计分钟数、换乘次数、经停楼层 |

## 预置场景（页面一键加载）

1. **常规逛展路线** — 主入口 → 热门展位（演示拥挤段）→ 美食广场
2. **跨层 + 餐饮 + 会议** — 1F→2F→3F 多次换乘
3. **不可达展位 C304** — 3F 东侧通道施工封闭（边级不可达诊断）
4. **闭展展位 B206** — 展位今日撤展（节点级不可达诊断），同行程的 C201、D3 仍正常规划

## 路径算法

- 图模型：76 个节点（展位/餐饮/会议室/入口/走廊/电梯/扶梯/楼梯）+ 90 条边
- 步行边代价：`distance × crowdFactor`（拥挤系数 1.00 / 1.15 / 1.45 / 2.00；
  避堵模式加强为 0.95 / 1.15 / 2.0 / 3.2）
- 垂直边代价：`固定耗时 × 步速 + 垂直距离`
- 最短路：Dijkstra（二叉堆），多目的地按选点顺序逐段求解
- 不可达诊断：全图 BFS（含封闭边）与实际可用图 BFS 对比，
  定位把目标区域与主网隔开的**割边（blocked cut-edge）**，提取封闭原因

## 目录结构

```
backend/
  venue_data.py   # 三层场馆拓扑：节点、通道、距离、拥挤度、封闭信息
  pathfinder.py   # 建图 / Dijkstra / 不可达诊断 / 中文步骤生成
  server.py       # 标准库 HTTP 服务：GET /api/venue、POST /api/route
frontend/
  index.html      # 三栏布局：选点表单 | 拓扑图 | 文字步骤
  app.js          # SVG 拓扑渲染、选点交互、路线高亮、步骤面板
  styles.css
run.sh            # 一键启动
```

## API

- `GET /api/venue` → 楼层、节点、边、拥挤度元数据
- `POST /api/route`
  ```json
  {"entrance":"E1","booths":["B102","C102"],"dining":"D1","meeting":"M301","avoidCrowd":false}
  ```
  返回每段路线（节点序列、边序列、里程/耗时/换乘统计、中文步骤）与 `unreachable` 诊断列表。
